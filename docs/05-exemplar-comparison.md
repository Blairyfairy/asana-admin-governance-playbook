# Exemplar Comparison

The official exemplar follows **Path B** (newly appointed super admin at a growing company). This project follows **Path A**, but the structure is the same. There are many valid approaches, and this table shows where the two line up.

## Scenario (exemplar)

A newly appointed Asana super admin at a growing company that recently expanded Asana to several new departments. The company needs ongoing practices for license management, user access control, and data compliance.

## Topics

| Exemplar topic | This project |
|---|---|
| Over-provisioning of licenses, leading to unnecessary costs | Topic 1: License usage and cost control |
| Inconsistent user access controls, potentially leading to data exposure | Topic 2: User access, guests, and role control |
| No clear process for responding to security incidents | Topic 3: Integrations, AI settings, and data security, including the breach response plan in `06-security-incident-response.md` |

## Checklist

| Exemplar checklist item | This project |
|---|---|
| Conduct monthly license audits | Item 1 |
| Regularly review guest accounts | Item 2 |
| Perform quarterly security checkups | Item 6 |
| Maintain a security breach response plan | Item 6 and `docs/06` |
| Review and update role-based access controls | Item 3 |
| Monitor integration policies | Item 4 |
| (not in exemplar) | Item 5: Asana AI and AI Studio review; Item 7: Insights monitoring and governance reporting |

## Project build

The exemplar starts from the **Workflow gallery operations project plan for IT teams** and customizes it. This project uses the same starting point, then adds sections per topic, custom fields for Priority and Topic, dated tasks with assignees, and a recurring quarterly review.
